TAUREON Synth Tool V4 0.1.0-alpha.2 is the second public Windows x64 preview.

**What changed since alpha.1**
- Auto tries Windows MIDI Services first and falls back to WinMM when WMS is unavailable or lists no routes; it never opens a port by itself. Either port field offers the backend choice on a fresh start, long port names are readable, and a failed connect leaves the port fields usable for a retry.
- The WMS backend now targets the Windows MIDI Services Developer Preview 9 API (`Windows.Devices.Midi2`) instead of the RC4 SDK and reports missing API, Legacy API mode and unreachable service separately. `--list-midi wms|winmm` lists routes or the error without opening a port.
- MIDI Monitor: follows the latest events and pauses when you scroll up; RX/TX and event-type filters with "All event types" and "Notes only" presets; MIDI 2.0 channel-voice messages are filtered correctly.
- A manually selected device profile can label known CCs; a conservative Waldorf Protein profile is included.
- SysEx Transfer puts raw bytes first; the exact TX route stays visible and is rechecked before Raw Send. The SysEx Manager tab is hidden.

**Download and start**
Extract the whole ZIP and start `TAUREON-Synth-Tool-V4.exe`; keep the DLL and plugin subfolders beside it. Windows 11 x64 is the primary target. The executable is unsigned. Verify the download with `SHA256SUMS-v0.1.0-alpha.2.txt`.

**Windows MIDI Services:** this ZIP does not include Microsoft's preview API files (`Windows.Devices.Midi2.dll`/`.pri`). WMS works only where Windows provides that API or you place permitted API files beside the EXE; otherwise use WinMM (Auto does this for you). This release does not install or reconfigure MIDI drivers or services.

**Alpha limitations:** Stage 5 is still open. Real MIDI/SysEx transfer through the product UI and physical-device restore have not passed hardware acceptance, and this build has not been tested on hardware yet. Native 150% and 200% display-scaling checks are outstanding. Back up important synth data, select exact RX/TX routes deliberately, and start with receive/inspection workflows. Please report bugs with reproducible steps and the build revision shown in the title bar or Diagnostics.
