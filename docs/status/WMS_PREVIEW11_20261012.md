`--probe-api <expected API DLL path>` argument. It uses the production transport
to enumerate routes, checks the actual loaded module via `GetModuleHandleW` /

origin. It prints route counts only, not endpoint names, IDs or host paths. The
probe is not registered in ordinary CTest and never opens an endpoint or sends

## Limits and CI

### Review correction: reused CMake caches

The pre-merge review identified that changing a CMake default alone does not
replace a cached dependency root. Reconfiguration now migrates the former
project-local Preview-10 default (including Windows backslash spelling), preserves
explicit custom roots, and rejects any selected WINMD whose hash is not the
pinned Preview-11 hash. This prevents stale SDK use even through a custom path.

The existing WMS-enabled build was deliberately reconfigured with the old default
and its cache moved to Preview 11. Incremental build passed; the expanded suite
passed 25/25 in 6.92 seconds, with no failure or skip. The added configure-only
regression checks both default path spellings, custom-root preservation and
stale-metadata rejection without SDK downloads, native MIDI or a compiler.
The original 24-test results above belong to the initial implementation.

The Product Owner reported a pending reboot. These checks describe the current
pre-reboot machine: Tools installer version 0.99.92.0, older installed Transports
1.0.35-preview.8, and an already running OS MIDI service. They do not establish
post-reboot behavior, a Transports update, physical receive/send, losslessness,
SysEx transfer, restore or native GUI acceptance. No driver, service, registry,
API-mode or physical-output change was made.

The push workflow additionally builds the installed WMS consumer and runs only
its registered non-native tests; the explicit API probe stays local/opt-in.
